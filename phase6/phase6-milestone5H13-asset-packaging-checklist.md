# Milestone 5H.13 — Gated game asset-packaging checklist

**Proposed approval checklist, not approved assets or packaging authorization. All unchecked gates remain unchecked. Commercial release: NO-GO.** Preserve the original prototype/source WAVs in place; do not copy any into public, src, dist or release archives during this audit. This plan does not alter5H.12.

## Gate A — Scope and evidence

- [ ] Record named project approval owner, date, intended territories/platforms and commercial use. This approval cannot create third-party rights.
- [ ] Choose WAV-only output distribution or separately approved model/code redistribution; default proposal is WAV-only, no Python/model/data runtime.
- [ ] Attach rights-condition closure evidence for every applicable R01–R11 item from the resolution report. Mark genuinely inapplicable items with supported rationale; do not simply tick UNKNOWN.
- [ ] Record listening/content acceptance per line/profile; preserve UNVERIFIED pronunciation/emotion fields until actually reviewed. No automated promotion from valid waveform to approved voice.

## Gate B — Exact asset register

- [ ] Create a future release manifest containing unique asset ID, exact dialogue ID/version and Telugu/English text hash; model/revision/speaker; speed/pause/seed and generator provenance; file hash/format/duration; source owner; rights evidence references/scope; attribution obligations; approval identity/date; destination and rollback source. Keep language/technical/rights approval fields separate.
- [ ] Match each static clip to the existing authoritative assistant branch; dynamic rewards, counts and mission-history facts stay text-only unless separately approved. Never encode fixture facts as personal progress.
- [ ] Explicitly list all denied/unapproved recordings and prototype roots. No accidental originals, variants, movies, reference recordings, training corpus, model weights or source tooling in shipping output.
- [ ] Preserve source WAVs,51 drafts, saves and rollback data; any future copy or transformation requires authorization and a new derived-file hash/provenance chain.

## Gate C — Notices and obligations

- [ ] Review the full5G.7 notice set and5H.13 scope resolution. Include exact applicable creator/model/dataset links, Rasa citation, CC BY link, change statements and supplied notices.
- [ ] Use an output-specific obligations assessment for WAV-only distribution. Conservative credits must not be presented as a substitute for unresolved permissions.
- [ ] If redistributing model/code/frontend/dependencies, include full applicable CC/MIT/CMU notices and dependency bill of materials. Audit applicable restrictive technical measures/additional terms on licensed components; do not claim the whole proprietary game must be open-source merely because a component is CC BY.
- [ ] No endorsement/actor identity claim, unauthorized movie audio or unsupported permission statement in credits or marketing.

## Gate D — Runtime and build protections

- [ ] Existing runtime rights guard remains fail-closed for unverified/missing entries through every route, including direct and cinematic calls; no mutable bypass used to ship denied material.
- [ ] Define an exact release allowlist rather than assuming the present catalogue-deny policy covers uncatalogued assets. Any change requires separate implementation approval.
- [ ] Existing Milestone3 policy and copyPublicDir=false remain intact unless an approved equivalent is tested. Runtime mute or rejection never counts as packaging exclusion.
- [ ] Prevent production imports/references to phase6 evaluation assets. No eager model/51-line downloads or cache residue in release artifacts.

## Gate E — Authorized release verification — NOT RUN HERE

- [ ] After separate approval, build clean output in a verified generated directory without deleting source/rollback files or touching saves. Run build/lint and representative text/game regressions.
- [ ] Inventory all emitted files, JS/CSS/map assets, renamed/hash-named audio, raw/base64 embeds, archives and offline/service-worker caches; compare hashes with exact allowlist and denied sources. Exact-byte scanning alone does not rule out transcoded copies; inspect transform/import pipelines and all audio-bearing outputs.
- [ ] Demonstrate zero unapproved asset paths, contents, aliases or derived clips in the release. Fail on unknown audio; do not hide absence of coverage as a PASS.
- [ ] Verify approved files actually decode/play in desktop and physical target mobile browsers, handle activation/errors/mute/pause/cinematic precedence, and preserve factual text fallback. Emulation is not physical-device proof.
- [ ] Verify protected files, preserved campaign copies and applicable save baselines read-only, with disposable test profiles only. Record modified files and original hashes.
- [ ] Review release manifest, credits, tests and unresolved exceptions, then obtain explicit project release authorization. No audit report auto-enables voice or grants legal permission.

## Rollback

Before any approved implementation/package action, snapshot affected source/config/manifest/notices without overwriting existing backups. On failure disable assistant voice, retain text-only behavior, restore only affected authorized changes and preserve evidence. Never reset campaign saves or delete the source prototype. Quarantine or remove a generated release only with appropriate authorization and verified path bounds. No rollback action was necessary in this audit.
