3. The exported `requireVerifiedMissionVoices(value)` can disable the boolean policy if a future caller passes false. Current production calls enable it; no false call was introduced or used in tests.
4. The current guard is a boolean approval gate, not a documentary contract/expiry/revocation/territory evaluator. No cleared recordings exist now. Future approval governance must not be mistaken for automatic validation of all legal conditions.
5. Original files remain in `public` as required, so direct development/source access and old archived builds are not governed by production-package exclusion. Use only the verified release output; do not distribute the whole workspace/old evidence builds as a release.
